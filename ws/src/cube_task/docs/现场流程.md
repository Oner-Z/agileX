# 现场流程（11/12–13 上机适配，11/14 比赛）

本文是上机时照着做的清单。按顺序做，每一步都写了预计时间和通过标准。不通过就查第 6 节
“出问题时怎么办”，不要带着问题进入下一步。本文没写到的情况：先按 `p` 停下，再商量。

约定：

- 所有命令都在包根目录运行：`cd ~/vision/ws/src/cube_task`。
- 工具用 `python3 -m cube_task <工具>` 启动，和 `ros2 run cube_task <工具>` 等价。`-h` 看全部参数。
- 只改 `config/site/*.yaml`，不改 `config/default.yaml`，不改代码。各配置项见 docs/配置说明.md。
- 没有显示器（SSH）时，带窗口的工具加 `--headless`：命令在终端输入，预览图存成文件，路径会打印出来。

实机部署脚本（按顺序用，每个 `--help` 看参数；日志在 `~/vision_runs/onsite/`）：

| 脚本 | 做什么 | 会动臂吗 |
|---|---|---|
| `bash scripts/arm_check.sh` | 拉起 CAN → 听 1 s 机械臂反馈帧 → 只读关节 / TCP / 夹爪 → MoveIt 桥接 + RViz 拖动控制（`--plan-only` 只规划） | 第 4 步确认后会 |
| `bash scripts/camera_check.sh` | USB（是否 USB 3）→ udev 规则 → 启动大白驱动 → 用 cube_task 取 RGB-D 帧 → RViz 显示 RGB、深度、点云 | 不会 |
| `bash scripts/handeye.sh` | 腕端相机手眼标定：拖动示教，相机测一次、指尖碰一次方块顶面中心，共 8 个点；再悬停核对 | 标定不动，核对会动 |
| `bash scripts/capture_dataset.sh <名字>` | 采集数据集：每帧存 RGB（`*_color.png`）、对齐深度和机械臂位姿 | 不会 |

顺序：`arm_check` 和 `camera_check` 都通过 → 量 TCP 写进 local.yaml → `handeye` 标定 → `teach_poses`
示教取物区、卡纸和观察位 → `handeye --verify-only` 悬停核对 → 颜色标定 / 果蔬学习 → 空跑 → 真抓。
上电前确认 J1 零点刻度线对齐。同一时间只能有一个程序控制机械臂：标定、示教、跑任务前先关掉 arm_check。

## 0. 安全规则（每次上机前读一遍）

1. 两人上机：**操作员**管键盘；**安全员**的手一直放在急停按钮上，不离开。
2. 第一次动臂用 `--speed 20`。空跑（第 11 步）通过之前不超过 20 %。
3. 会动臂的工具（`run_task`、`calib_verify`、`color_calib --observe`）先打印要做的动作，第一次运动前要输入
   `y` 确认。看清楚动作和速度再确认。
4. 默认速度是 `robot.speed_percent`（30 %）。`--speed` 只能调低；`run_task` 要调高必须再加 `--allow-faster`。
5. 运行中怎么停（在运行 run_task 的终端里按，不用回车）。run_task 在第一个动作之前就开始读按键，移到观察位的
   过程中 p / 空格 / e 已经有效。移动过程中按的回车不算开始，要等出现 `Press Enter to start the timed run` 以后
   再按回车。

| 操作 | 效果 | 什么时候用 |
|---|---|---|
| `p` 或空格 | 不再发新指令，机械臂原地保持，电机保持使能 | 首选：看到不对就按 |
| `e` | 电子急停：机械臂慢慢下沉；之后要把臂放回支架、断电重启才能再用 | 马上要撞，来不及 |
| `Ctrl-C` | 发 stop、存日志后退出；**已经发给控制器的那一条运动会走完** | 程序卡住时 |
| 急停按钮 | 硬件急停 | 最后手段，安全员负责 |

6. 程序在正常流程里从不调用 `disable()` / `reset()`（电机掉电，臂会落下）。唯一的例外是工具里的
   `x = exit_teach_mode`：要手动输入 `EXIT` 确认，而且只有六个关节都在零位 0.05 rad（2.9°）以内、臂折叠放在
   支架上时工具才执行，否则直接拒绝。它的真实顺序是：先用 move_js（MIT 模式，没有平滑、没有轨迹规划）直接
   跳到全零关节位并等 2 秒，然后电子急停、reset()（电机立即断电）、重新使能、move_j 到零位，不经过任何安全
   检查。整个过程手不要碰机械臂，也不要托着它，直到工具打印 `exit_teach_mode done`。

   离开拖动示教模式的首选方法是**再按一次臂上的示教按钮**。如果之后仍是 TEACHING_MODE：固件 S-V1.8-5 及以上
   用 `c = take CAN control`（输入 `CAN` 确认，只发使能和 0x151 模式帧，不发运动指令；还没在真机上试过，第一次
   在臂放在支架上时试）；S-V1.8-5 以下只能 reset：趁拖动模式还开着，把臂拖回支架折叠到零位、松手，再用 `x`，
   或在支架上断电重启。`c` 和 `x` 在 calib_verify、color_calib --observe 提示 drag-teach mode 时输入。
   `check_setup --live` 会打印固件版本和对应的退出方式。
7. 相机由工作人员安装和标定，不能移动、更换、调整。外参有问题先告诉工作人员。用 `calib_verify --apply`
   或 `calib_points` 在软件里改外参之前，先问清楚是否允许。
8. 每次运行会动臂的命令之前，确认没有人的手在臂的工作范围内。

## 1. 时间总览

11/12 第一次上机按下表顺序做，合计约 2.5 h。每一步的细节在第 3 节。

| 步 | 内容 | 时间 | 通过标准 |
|---|---|---|---|
| 1 | 出发前准备（前一天，第 2 节） | 40 min | 离线检查全部通过，备份能读 |
| 2 | 接线、CAN | 5 min | `OK: can0 is UP at 1000000 bit/s` |
| 3 | 相机驱动和话题 | 5 min | 彩色、深度、内参 3 个话题都有数据 |
| 4 | 问官方参数，填 config/site | 20 min | config 组只剩示教和模型相关的 FAIL |
| 5 | `check_setup --live` | 2 min | modules / can / ros / live 组没有 FAIL |
| 6 | `view` 看画面 | 5 min | 每个物体一个实例，尺寸误差 ≤ 5 mm，找到桌面 |
| 7 | `teach_poses` 示教区域和观察位 | 15 min | 区域都可达（OK 或 tilt），自检无 FAIL |
| 8 | `calib_verify` 核对外参 | 10 min | 平均偏差 ≤ 5 mm，离散（RMS）≤ 3 mm，h 和 `expected h` 差 ≤ 5 mm |
| 8b | `calib_points` 重估外参（备用） | 15 min | RMS ≤ 3 mm，复核偏差 ≤ 3 mm |
| 9 | `color_calib`（L1） | 5 min | 预览里每个方块颜色都对，无重叠警告 |
| 10 | `teach_classes`（L2） | 20 min | 每类 ≥ 8 个样本，留一法准确率 ≥ 95 % |
| 11 | 空跑 `--dry-run --speed 20` | 每个任务 5 min | `exit code 0`，每个悬停点都对准 |
| 12 | 单个物体真抓 | 15 min | 每种颜色 / 代表性果蔬各成功 1 次 |
| 13 | 整轮限时，逐步提速 | 30 min | L1 3/3 ≤ 180 s，L2 6/6 ≤ 300 s，连续 2 轮 |
| 14 | 保存配置、备份 | 5 min | U 盘上有新备份 |

**时间不够时**（只有 1 h）：做 2、3、4、5、7、8、11（L1）、12、14，把 9、10、13 留到 11/13。
L2 样本可以先用 `capture` 每类录 2 分钟（第 10 步的“离线做法”），回去用 `teach_classes --from-dir` 训练。

## 3. 11/12 第一次上机：逐步操作

### 第 2 步：接线和 CAN（5 min）

1. 确认机械臂已上电、放在支架上，急停按钮已松开。
2. USB-CAN 适配器插到我们的电脑上。
3. 运行（要输入一次 sudo 密码）：

```bash
bash scripts/can_up.sh
```

**通过**：`OK: can0 is UP at 1000000 bit/s (can state ERROR-ACTIVE).`

**不通过**：

- `CAN interface can0 does not exist`：脚本会列出现有的 CAN 口和像 CAN 适配器的 USB 设备。名字不是 can0
  （例如 can1）时运行 `bash scripts/can_up.sh can1`，并在 config/site/local.yaml 写 `robot.can_channel: can1`。
  插了多个适配器时，用脚本打印的官方命令 `can_activate.sh can0 1000000 <usb-bus-info>` 选端口。
- `BUS-OFF`、`ERROR-PASSIVE`：查 CAN 线和臂的电源，再运行一次 `bash scripts/can_up.sh`。
- 别的程序（官方 demo、agx_arm_ctrl 节点）正在控制机械臂时，不要运行这个脚本，也不要同时开两个控制程序。
- 只想看状态、不改设置：`bash scripts/can_up.sh --check`（不用 sudo，没准备好时退出码 1）。

### 第 3 步：相机驱动（5 min）

用工作人员给的启动命令。奥比中光 ROS 2 驱动的常见写法（深度对齐到彩色）：

```bash
ros2 launch orbbec_camera dabai.launch.py depth_registration:=true
```

另开一个终端检查：

```bash
ros2 topic list | grep -E 'image|camera_info'
ros2 topic hz /camera/color/image_raw
ros2 topic hz /camera/depth/image_raw
```

**通过**：彩色图、深度图、彩色 camera_info 三个话题都在，帧率 ≥ 10 Hz。记下实际的话题名（第 4 步写进
local.yaml）。

**不通过**：话题不在 → 驱动没起来，或 `ROS_DOMAIN_ID` 和驱动所在的机器不一样（`echo $ROS_DOMAIN_ID`）。
帧率很低 → 换 USB 3 口，不用 USB 集线器。

### 第 4 步：问官方参数，填 config/site（20 min）

逐项问清楚，并写下来源（谁说的、哪个文件）。不知道的项不要随便填一个数让检查通过。

| 要问 / 要查 | 写到哪里 | 怎么核对 |
|---|---|---|
| 彩色、深度、内参的话题名；深度是否已对齐彩色；深度单位 | local.yaml `camera.ros.*` | 第 3、5 步 |
| 外参：组委会不提供，用 `bash scripts/handeye.sh` 自己标（腕端相机 T_flange_camera） | `config/site/extrinsics.yaml` | 第 8 步悬停核对 |
| 夹爪型号：70 mm 还是 100 mm 行程 | local.yaml `robot.gripper.max_width` | 第 5 步读到的夹爪宽度 |
| 法兰端面到指尖中心（闭合时）的距离 | local.yaml `robot.tcp_offset` 的第 3 个数 | 用尺量；第 8 步悬停高度 |
| L1 方块的边长和颜色 | local.yaml `perception.l1_block_size`；tasks.yaml `tasks.L1.labels` | 用尺量；第 6 步 |
| 区域 / 容器的名字、位置，哪一类放哪里 | tasks.yaml `class_to_zone`；位置在第 7 步示教 | 看场地 |
| L2 的正式类别表 | tasks.yaml `tasks.L2.labels` | 官方清单 |
| L1 的“指定目标”怎么给（口头？纸条？有没有顺序？） | 比赛时的 `run_task --targets` | 问裁判 |
| 开始计时前能不能把臂移到观察位 | 比赛时用不用 `--no-wait`（第 5.2 节） | 问裁判 |
| 重启 / 维修的具体做法；能否自己在软件里改外参 | 第 5.3 节、第 8 步 | 问裁判 |
| 能否在上机时采集图像并带走 | `capture`、`teach_classes` | 问工作人员 |
| 机械臂固件版本 | local.yaml `robot.firmware` | 第 5 步打印的 firmware |

外参只有腕端相机这一种（比赛没有固定相机），文件里存 T_flange_camera（相机光学坐标 -> 法兰 link6）。
固定相机的标定（T_base_camera、`mount: eye_to_hand`、`parent_frame: base`）程序会拒绝加载。

`config/site/local.yaml`（按问到的值改；不知道的行删掉，用默认值）：

```yaml
robot:
  can_channel: can0
  speed_percent: 30                  # 第 13 步提速时改这里
  tcp_offset: [0.0, 0.0, 0.1425, 0.0, 0.0, 0.0]   # 第 3 个数 = 法兰到指尖中心 (m)

    info_topic: /camera/color/camera_info

  l1_block_size: 0.05                # L1 方块边长 (m)：官方 50 mm
```

`config/site/tasks.yaml`（区域名要和第 7 步示教时用的名字一致）：

```yaml
tasks:

    labels: [red, green, yellow]
    class_to_zone: {red: zone_red, green: zone_green, yellow: zone_yellow}
  L2:
    classifier: knn
```

`config/site/extrinsics.yaml`：组委会不提供标定文件（答疑 Q8/Q9），正常由 `bash scripts/handeye.sh`
（calib_points）写入。手写时用下面任一种写法；数值是仿真里腕端相机的例子（法兰 -x 方向 70 mm、法兰面前 30 mm）。

```yaml
# 写法 A：4x4 矩阵 T_flange_camera（相机坐标 -> 法兰坐标），单位 m
mount: eye_in_hand
parent_frame: flange
matrix:
  - [0.0000, 1.0000, 0.0000, -0.0700]
  - [-1.0000, 0.0000, 0.0000, 0.0000]
  - [0.0000, 0.0000, 1.0000, 0.0300]
  - [0.0000, 0.0000, 0.0000, 1.0000]
```

```yaml
# 写法 B：标定结果是反方向（法兰 -> 相机）。键名写 T_camera_flange，加载时自动求逆
T_camera_flange:
  - [r11, r12, r13, tx]
  - [r21, r22, r23, ty]
  - [r31, r32, r33, tz]
  - [0, 0, 0, 1]
```

```yaml
# 写法 C：平移 (m) + 四元数 (x, y, z, w)。结果是 (w, x, y, z) 时把 w 挪到最后
mount: eye_in_hand
parent_frame: flange
translation: [-0.0700, 0.0000, 0.0300]
quaternion: [0.0, 0.0, -0.7071, 0.7071]
```

外参是相对 TCP 的
（`parent_frame: tcp`）时，必须同时写 `tcp_offset: [x, y, z, roll, pitch, yaw]`（m、rad），填标定时驱动用的
TCP 偏移；程序加载时把它换算成 T_flange_camera，之后改 `robot.tcp_offset` 不会移动相机。没写 tcp_offset 会
拒绝加载；驱动的 tcp_offset 是全 0 时直接写 `parent_frame: flange`。

handeye_calibration_ros 的 JSON（`position` + `orientation`）可以原样存成 `config/site/extrinsics.json`，再在
local.yaml 里写 `camera: {extrinsics_file: config/site/extrinsics.json}`；calib_verify --apply 和 calib_points
的 `w` 写回这个文件时仍然写 JSON。外参文件不要用 .npy：工具不能写回 .npy（calib_verify --apply 和
calib_points 改写到同名 .yaml 并提示 `--set camera.extrinsics_file=...`）。其他格式见 docs/配置说明.md 第 4 节。

填完后检查（不动臂）：

```bash
python3 -m cube_task check_setup --skip can,ros
```

**通过**：config 组剩下的 FAIL 只有 `no zones configured`（第 7 步解决）、`no extrinsics`（第 8 步前用
`scripts/handeye.sh` 解决）和 `knn model file missing`（第 10 步解决）。外参那一行是 `[PASS] extrinsics: mount ..., translation [...]`。
WARN `perception.table.expected_z is not set` 也在第 7 步（`p`）解决。

**外参粗查**：translation 是相机在法兰坐标系里的位置，应该只有几厘米（用尺量相机到法兰中心核对）。
平移大于 0.2 m 或位置明显不对，说明方向反了（换写法 B）；毫米单位会直接报错
`Units must be meters (millimeters?)`，把平移除以 1000。

### 第 5 步：check_setup --live（2 min，不动臂）

```bash
python3 -m cube_task check_setup --task L1 --live
```

它只读机械臂（连接但不使能），再从相机取图。

**通过**：modules、can、ros、live 组没有 FAIL。live 组里应该有：

- `arm: ready`、`arm: joints [...] deg`、`arm: TCP [...] mm`、`arm: firmware ...`
- `gripper: width ... mm`。出现 `gripper opens wider than robot.gripper.max_width` 警告说明是 100 mm 夹爪，
  把 `max_width` 改成 `0.100`。
- `camera: <宽>x<高> color from ros`、`camera: intrinsics fx ...`、`camera: NN % valid depth in the image`
  （≥ 50 %）、`camera: NN frames/s`（≥ 5）。臂在支架上时腕端相机看不到取物区，取物区深度那一项是
  WARN `... (wrist camera: valid only at the observe pose)`，正常。

config 组里第 4 步说的那几项 FAIL 还在是正常的。

第一次上机时顺便做（2 min，不动臂）：

- 臂放在支架上时记下 `check_setup --live` 打印的固件版本（`arm: firmware ...` 那一行也写着离开拖动示教要不要
  reset），再看 `arm: joints [...] deg`：六个关节都在 ±2.9° 以内时，`x` 才能用。
- 按一次示教按钮（进入拖动），再按一次，再运行 `check_setup --live`：仍显示 TEACHING_MODE 时，按第 0 节第 6 条
  处理（c 或 x），并把结果记下来。这时还没有区域和观察位，可以用 `calib_verify --point 0.30 0 0`：它在
  drag-teach mode 提示时接受 c / x；之后问 `Start moving?` 时输入 `n`，臂不动。

**不通过**：每个 FAIL 下面有一行 `fix:`，照做后重跑。常见情况见第 6 节。

### 第 6 步：view 看画面（5 min，不动臂）

取物区里分开放 3 个方块（L1）或几个果蔬（L2）：

```bash
python3 -m cube_task view --task L1
```

左图是感知叠加图：实例掩码、标签和分数；被拒绝的实例是灰色并写原因；取物多边形和区域按外参投影上去。
右图是深度伪彩色。下面一栏是桌面平面、各阶段耗时和帧率。按键：`d` 打印检测表，`s` 存一帧，`q` 退出。

腕部相机（eye_in_hand）：先用拖动示教把臂停在能看到整个取物区的位置，view 用当前的法兰位姿算相机位姿。

**通过**：

- 每个物体正好一个实例；L1 的标签正确（L2 训练之前显示 unknown）。
- 按 `d`：`LxWxH mm` 和实物差 ≤ 5 mm（35 mm 方块约 35x35x35）；`center_base mm` 和尺量的位置大致一致。
- 面板里有 `table: z ... mm at the pick-area center, tilt ... deg`：找到了桌面，tilt 小于 2 度，z 和桌面高度一致
  （基座装在桌面上时约为 0）。
- 掩码边缘和图里物体的边缘重合（深度和彩色对齐）。
- 第 7 步示教完取物多边形之后再看一次：投影的多边形框住了取物区。

顺手存几帧现场图，回去做回放和训练：

```bash
python3 -m cube_task capture --session blocks_1112 --count 10 --interval 1
```

**不通过**：见第 6 节的“深度没对齐”“桌面找不到”“外参方向错”“两个方块认成一个”。

### 第 7 步：teach_poses 示教区域和观察位（15 min，工具不动臂）

一个人扶住机械臂，按臂上的示教按钮进入拖动示教模式，用手把臂拖到位；另一个人在电脑上输入命令。
工具只读位姿，从不动臂。

```bash
python3 -m cube_task teach_poses --task L1
```

按工具提示的顺序做：`p` → 每个区域 `z` → `o` → L2 的每个观察视角 `v` →（可选）`h` → `w`。

| 命令 | 做什么 | 写入的配置 |
|---|---|---|
| `p` | 用闭合的指尖依次碰取物区的 4 个角（贴着桌面）。一定要做：它写的 expected_z 是抓取高度和安全检查桌面高度的下限 | `perception.roi.pick_polygon`、`perception.table.expected_z` |
| `z zone_red` | 指尖碰区域底面的中心；再回答尺寸（m）、壁高（m，平垫子填 0），可选碰第二点定朝向 | `zones.zone_red.*` |
| `d veg_bin` | 从 poses.yaml 删除区域（`u` 可撤销，`w` 写入；`d` 不带名字时会问）。同名区域还写在别的文件里（default.yaml、其他 overlay、--config / --set）时会警告：合并配置删不掉别的文件里的键，要去那个文件里删；还有 `class_to_zone` 指向它时也会警告 | 删除 `zones.veg_bin` |
| `o` | 把臂拖到观察位后输入，记录当前关节角：停在取物区上方，腕端相机能看到取物区（L2 再用 `v` 示教其他视角） | `robot.poses.observe_joints` |
| `v` | 把臂拖到一个观察视角后输入，追加到视角列表（`v clear` 清空）。一个视角拍不全取物区时（L2 一定拍不全），按扫描顺序示教 2–4 个视角，第一个就是开始时去的位置；相邻视角重叠至少一个物体的宽度，每个物体都要完整落在某一个视角里。run_task 开始时打印覆盖率（`observe views cover ..%`），低于 95% 时补视角 | `robot.poses.observe_views` |
| `h` | 记录当前关节角为 home 位姿（可选） | `robot.poses.home_joints` |
| `l` / `u` | 列出已记录的 / 撤销上一条 | |
| `w` | 写入 config/site/poses.yaml（旧文件备份成 poses.bak_<时间>.yaml） | |
| `q` | 退出（有没写入的改动会问） | |

- 区域名要和 tasks.yaml 的 `class_to_zone` 里的名字一样。`z` 会列出 `zones in tasks.*.class_to_zone`。
- 每个点停稳再回车：工具读 8 次求平均，抖动超过 3 mm 会提示重来（`--samples`、`--max-jitter-mm`）。
- L2 的容器再做一次 `teach_poses --task L2`。所有区域都在同一个 poses.yaml 里。
- 场地布局变了（区域改名或挪位置）时，先用 `d <旧名>` 删掉旧区域再示教新的，否则旧区域加上 zone_exclude_margin
  的范围仍会把取物区里的物体排除掉。
- 自检 WARN `zone X grown by perception.roi.zone_exclude_margin ... overlaps the pick polygon` 或
  `zone X is not used by any tasks.*.class_to_zone`：多半是旧布局留下的区域，取物区里压着它的物体都会被忽略
  （touches_zone）。用 `d X` 删掉它再 `w`。
- `o` / `h` 读到的关节角在限位外 0.01 rad（0.573°）以内时（臂折叠在支架上时 joint2 / joint3 正好在限位上），
  按限位记录并打印 note；超出更多时拒绝，提示里的角度是度（3 位小数）。
- 做完先把臂拖回支架折叠到零位，再按一次示教按钮，离开拖动示教模式。如果 `check_setup --live` 仍显示
  `TEACHING_MODE`：固件 S-V1.8-5 及以上，在 calib_verify 提示 drag-teach mode 时输入 `c`，再输入 `CAN`（接管 CAN
  控制，不动臂）；S-V1.8-5 以下，确认臂折叠在零位后输入 `x`，再输入 `EXIT`，或在支架上断电重启。

**通过**：`w` 之后打印的可达性表里，每个区域是 `OK` 或 `tilt N deg`，没有 `unreachable`；最后一行是
`self check (L1, config only): no FAIL items`（L2 在第 10 步之前会有 knn model 的 FAIL）。

**不通过**：区域 `unreachable` → 区域离基座太远或太高（PiPER 的 joint5 限位让竖直的工具只能放到不高的地方，
仿真里的区域都在半径 0.40 m 以内），和工作人员确认区域位置，并检查 `robot.tcp_offset`。观察位警告夹爪挡住
视野 → 把臂停得更靠边。

### 第 8 步：calib_verify 核对外参（10 min，会动臂）

取物区里分开放 3–5 个方块（中心和几个角）。先离开拖动示教模式（还在拖动示教模式时工具会提示，见第 7 步最后一条）。

```bash
python3 -m cube_task calib_verify --task L1
```

默认速度 20 %，每个动作先打印，第一次运动前要输入 `y`。流程：移到观察位 → 拍照识别 → 对每个物体，把指尖中心
移到检测到的顶面上方 30 mm（`--hover`）→ 你量“真实物体顶面中心相对指尖中心”的偏差，输入 `dx dy`（毫米，
基座坐标系：+x 远离机器人，+y 是机器人的左边），可选第 3 个数 h = 指尖离桌面的高度（工具会打印期望值）
→ 下一个物体 → 回观察位、张开夹爪。最后打印每个物体的偏差、平均修正量 d 和离散度。`s` 跳过一个物体，`q` 停止。

量法：从正上方顺着手指往下看，或用钢尺先沿 x、再沿 y 量，精确到 1 mm 左右就够。

| 结果 | 怎么办 |
|---|---|
| 平均 d 的 x、y 都 ≤ 5 mm，离散（RMS）≤ 3 mm | 通过，外参不动 |
| 平均 d 在 5–20 mm，离散 ≤ 3 mm（整体平移） | 允许的话加 `--apply` 重跑：确认后写入修正后的外参（旧文件备份），再跑一次确认 ≤ 3 mm |
| 离散 > 5 mm，或偏差几厘米以上、各个物体偏的方向不一样 | 旋转或方向错了：回第 4 步核对外参的方向；还不行做 8b |

另外：h 要量，并且和工具打印的 `expected h` 相差 ≤ 5 mm。`perception.table.expected_z` 必须已设置（teach_poses 的
`p`），没设置时 run_task 自检会 WARN。打印 `WARNING: table z differs from the taught table ... by N mm` 说明外参 z
方向有偏差：这时安全检查和抓取高度用两者中较高的桌面（示教的桌面是下限），指尖不会低于真实桌面，但要按本步
修正外参。

只查 TCP（不用相机）：`calib_verify --point 0.30 0.00 0.00`，指尖停在基座坐标 (0.30, 0, 0) 上方 30 mm，用尺量
位置和高度。只有高度不对时，是 `robot.tcp_offset` 的第 3 个数不对。

### 第 8b 步：calib_points 现场重估外参（备用，15 min，工具不动臂）

只在第 8 步发现外参明显错，并且工作人员同意（或给不出正确外参）时做。工具只读位姿，臂用拖动示教模式。

```bash
python3 -m cube_task calib_points
```

每个点（默认 6 个，`--points`）：

1. 取物区里只放一个方块（L1 方块就行），放到一个新位置。各点要分散：4 个角、中心、边上，不要排成一条线。
2. 回车：相机测量方块顶面中心（平均 5 帧，帧间差超过 2 mm 会要求重测）。测量时臂不要挡住方块，也不要动。
3. 拖动臂，让闭合的指尖中心正好碰到方块的**顶面中心**，停稳，回车。
4. 从第 4 个点起，工具会预测碰点的位置；碰的位置离预测超过 10 mm 会马上提示（多半是碰歪了，`u` 撤销重来）。

点数够了以后工具求解，打印每个点的残差和 RMS、可疑的点（`d N` 删除第 N 个）、相机视角、相机高度、桌面倾斜、
和旧外参的差别。`w` 写入 camera.extrinsics_file（旧文件备份），`a` 再加一个点。每个点都立即存盘，中断后用
`--resume <pairs.json>` 接着做。

**通过**：RMS ≤ 3 mm，没有大于 3 mm 的离群点，相机高度和卷尺量的一致。写完后重做第 8 步，平均偏差 ≤ 3 mm。

指尖位置按 `robot.tcp_offset` 算，所以先确认 TCP 长度量对了。有打印的 ArUco 码时也可以用
`--target aruco --aruco-size 0.05`（黑框边长，m）。

### 第 9 步：color_calib 标定方块颜色（L1，5 min，不动臂）

先用第 6 步的 view 看：方块放在取物区不同位置、在比赛灯光下颜色都识别对，就可以跳过这一步。

```bash
python3 -m cube_task color_calib
```

1. 把本轮的方块放进取物区。工具拍一张，给有效实例编号，打印每个实例的色相、饱和度、亮度和尺寸。
2. 输入每个编号的颜色：`0 red; 1 green; 2 blue`（画面里只有一种颜色时用 `all red`）。颜色名必须在
   `tasks.L1.labels` 里。一行里有一处写错，整行都不生效。
3. 挪动方块或换个角度，`c` 拍新的一张，再标一次。每种颜色至少要 2 张（`--min-views`）。
4. `p` 预览：用刚算出的区间给当前画面分类；`s` 汇总样本数、区间和警告。
5. `w` 写入 config/site/colors.yaml（`perception.classifier.color.classes`，旧文件备份）。这次没有标定的颜色
   保留原来的区间（`--replace` 时丢掉）。

**通过**：`p` 里每个实例的 predicted 和 assigned 一样；`s` 没有 overlap 警告（两种颜色的区间重叠）。写完后用
view 再看一次。其他命令：`u` 撤销上一行，`m H SV` 改色相 / 饱和度余量后重算，`h` 帮助，`q` 退出。

### 第 10 步：teach_classes 录 L2 样本（20 min，不动臂）

```bash
python3 -m cube_task teach_classes --task L2
```

1. 取物区里分开放 3–6 个果蔬。工具拍一张，给有效实例编号。
2. 标注：`0 apple; 1,2 banana`；画面里只有一类时用 `all apple`。不在 `tasks.L2.labels` 里的标签要再确认一次。
3. 挪动、转动物体（换位置、换朝向、换朝上的面），`c` 拍下一张，再标。
4. 每类至少 8 个样本，来自取物区的不同位置。`s` 看每类的样本数；`e` 做留一法评估，打印混淆表。
5. `w` 写入 models/knn_model.npz（旧文件备份；旁边的 knn_model_report.json 记录每类样本数和准确率）。
   加 `--append` 在已有模型上继续加样本。

**通过**：留一法准确率 ≥ 95 %；没有 `are confused` 警告，尤其是要放进不同容器的两类之间；没有
`fewer than 8 samples` 警告。写完用 `view --task L2` 看标签对不对。

**单物体 + 拖动示教多视角的做法**（推荐：不用逐个编号标注）：

```bash
python3 -m cube_task teach_classes --task L2 --label cucumber --auto
```

1. 桌上只放一个黄瓜。按臂上的示教按钮，用手拖动机械臂从不同高度、角度看它；每次停稳 0.6 s 且离上一张
   至少 3 cm / 8°，就自动拍一张，画面里只有一个有效实例时自动标成 `cucumber`（有几个就不标）。
   也可以不加 `--auto`，每个视角按 `c`。中间可以换个摆法、翻个面。
2. 换下一类：按回车输入 `single pear`，桌上换成梨，继续拖。六类都拍完后 `e` 评估、`w` 写入。
3. 多物体测试：输入 `single off`，桌上摆几个不同的果蔬，`c` 拍一张。画面里会用当前样本预测
   （`#0 pear?`）；错的按编号改（`2 potato`），再按 `y` 把剩下的预测全部确认。确认和改正的都存成样本，
   终端打印 `predictions right so far: 17 / 20 (85%)`，`s` 也能看。准确率稳定在 95 % 以上就 `w`。
4. 拖动示教结束后控制器还是 TEACHING_MODE：跑会动臂的工具前用 `calib_verify` 的 `c` 切回 CAN 控制。

**每个视角都存盘，标错了事后改**：`teach_classes` 把每次拍的 RGB-D、机械臂位姿、实例编号和标签存到
`~/vision_data/<时间>_teach_L2/`（启动时打印目录；`--no-record` 关掉）。没按 `w` 就退出也不会丢：

```bash
python3 -m cube_task teach_classes --task L2 --review ~/vision_data/<时间>_teach_L2 [更多目录 ...]
```

- 重新分割存下的画面，每个样本一个编号（一个目录时 `视角#实例`，如 `12#0`；多个目录时 `2:12#0`）。
- 每类一张拼图写到 `<目录>/review/<类>.jpg`，和邻居不一致的样本（可能标错）红框标出，
  `suspects.jpg` 只放这些。终端也列出 `12#0 pear->potato`。
- 改标签 `12#0 potato`，删样本 `12#0 x`（可用 `;` 一次写多个）；`e` 评估，`w` 写模型并更新各目录的
  `labels.json`（旧文件备份）。改了分割参数后再 `--review` 一次就是用新参数重新训练，不用重拍。

**离线做法**（上机时间紧时）：每类单独录一段，回去再训练（不需要硬件，用 config/site 里的外参）：

```bash
python3 -m cube_task capture --session apple --count 20 --interval 1     # 只放苹果，录的时候挪动它们
python3 -m cube_task capture --session banana --count 20 --interval 1
python3 -m cube_task teach_classes --task L2 \
    --from-dir ~/vision_data/<日期>_apple ~/vision_data/<日期>_banana
```

目录名去掉日期前缀就是标签；不一样时写成 `apple=<目录>`。这些图也能用来训练 YOLO（docs/yolo.md）。

### 第 11 步：空跑（每个任务 5 min，会动臂）

物体照比赛那样摆好：

```bash
python3 -m cube_task run_task --task L1 --dry-run --speed 20
```

run_task 在真机上的流程：

1. 打印摘要：配置来源、限时和个数、`labels`（标签 -> 区域）、区域坐标、相机和外参、速度、观察位、分类器、
   机械臂状态和关节角、日志目录。**逐行看**，特别是标签到区域的对应和速度。
2. 完整自检（臂、相机、配置）。有 FAIL 就拒绝（exit code 2），什么都不使能、不动。
3. 打印 `About to: enable the motors, move to the observe pose, ...`，问 `Start on the REAL robot? (y/n)`。输入 `y` 回车。
4. 使能电机。夹爪既没全开也没全合时，先把夹爪再合拢 8 mm，检查有没有夹着东西（第 5.3 节）。TCP 低于搬运高度时
   先竖直抬起。移到观察位，张开夹爪。腕部相机（eye_in_hand）时在观察位再查一次能不能看到取物区。然后提示
   `Press Enter to start the timed run`，这以后按的回车才开始计时。
5. 空跑时，指尖停在每个抓取位姿上方 5 cm（`runner.dry_run_hover`）和每个放置位姿上方，夹爪始终不闭合。
6. 正常结束后回原点（`robot.poses.home_joints`，默认全零；低位先竖直抬起），打印每个物体一行的表和
   `exit code`。`runner.return_home_at_end`：`home`（默认）| `observe` 回观察位 | `false` 停在原地。

**看什么**：每次悬停时指尖中心是否在物体正上方；手指张开的方向是否横跨物体（方块对着两个平行面）；转运和放置时
手臂、手指、线缆有没有碰到容器壁或别的物体。

**通过**：`exit code 0 (round complete)`；表里每个物体的 stage 是 `dry_run_done`；过程中没有碰撞风险。
L2 同样空跑一次：`--task L2`。

### 第 12 步：单个物体真抓（15 min，会动臂）

取物区里只放 1 个物体：

```bash
python3 -m cube_task run_task --task L1 --speed 20 --set tasks.L1.required=1
```

**通过**：表里一行 `yes  done`，物体在正确的区域里，夹爪闭合时没有推动物体。每种颜色做一次。L2 选大的（苹果、
橙子）、长的（香蕉、玉米）和矮的各做一次：`--task L2 --set tasks.L2.required=1`。

失败时看表里的 `stage` 和 `error`（含义见第 6 节和 docs/仿真与测试.md 第 5 节），修好再继续。

### 第 13 步：整轮限时，逐步提速（30 min，会动臂）

按比赛那样摆放。速度从 20 % 开始，每次完整通过（全部放对、没有险情）才提高一档：

```bash
python3 -m cube_task run_task --task L1 --speed 20
python3 -m cube_task run_task --task L1                            # robot.speed_percent（30）
python3 -m cube_task run_task --task L1 --speed 40 --allow-faster
```

### 5.2 一轮的操作

`scripts/start.sh` 依次做：进入工作空间，source ROS 和 `install/setup.bash`，检查 CAN（`can_up.sh --check`），
运行 `check_setup --task <任务>`，然后 `run_task --task <任务> --mode real <其余参数>`。检查有 FAIL 时停下
（exit 1，`--force` 可以强行继续，不建议）。

**最简单：`bash scripts/run_L1.sh` / `bash scripts/run_L2.sh`**（11/13 起）：自检通过后不问 y、不等回车，
直接到观察位开始计时抓取（脚本自动加 `-y --no-wait`）。要恢复下面情况 A 的两次确认：`ASK=1 bash scripts/run_L2.sh`。

**情况 A：允许开始前把臂移到观察位**（start.sh 的默认做法）

```bash
bash scripts/start.sh L1 --targets red,blue,green
```

1. 看摘要：`targets` 是裁判给的目标和顺序；`labels` 里每个目标都有区域；`speed` 是练习时通过的速度。
2. 自检通过后问 `Start on the REAL robot? (y/n)`：输入 `y` 回车。臂移到观察位，张开夹爪。
3. 提示 `Press Enter to start the timed run`：告诉裁判“准备好了”。**听到开始信号时按回车**，然后手离开键盘，
   只留着 `p` / `e` 备用。

**情况 B：开始信号之前不许动臂**

```bash
bash scripts/start.sh L1 --targets red,blue,green --no-wait
```

停在 `Start on the REAL robot? (y/n)` 等信号，**听到开始信号时输入 `y` 回车**。移到观察位和张爪的几秒在程序
开始计时之前，但算在官方时间里，可以加 `--set tasks.L1.time_limit_s=175` 让程序按少几秒来安排。

其他任务：

- L2：`bash scripts/start.sh L2`

`--targets` 的写法：逗号、中文逗号或空格分隔，不分大小写。只抓这些标签；每次先抓列表里最靠前、当前看得到的
那个。每个目标都要在
`class_to_zone` 里有区域，否则拒绝启动（exit 2）。**目标个数少于 3 时**同时加
`--set tasks.L1.required=<目标个数>`，否则放完以后会报 INCOMPLETE（exit 1）。

运行中：不碰机械臂，不碰物体。安全员的手放在急停上。

腕部相机每次放置后回观察位取图（示教了多个观察位时：开始先扫完所有视角，之后只回目标所在的视角）。

结束：正常结束后程序回原点（`runner.return_home_at_end: home`；`observe` 回观察位，`false` 停在最后
动作结束的位置；故障或中止时不动），打印结果表和 `exit code`：

| exit code | 含义 |
|---|---|
| 0 | 全部完成 |
| 1 | 结束了但没全部完成（超时、没有可抓的目标、按了 `p`） |
| 2 | 动臂之前就拒绝了（参数、配置、自检 FAIL、没有确认） |
| 3 | 故障（连接或使能失败、运动故障、急停、程序异常） |
| 130 | Ctrl-C |

### 5.3 中途出故障

1. 马上要撞：按急停按钮或 `e`。其他情况按 `p`（停止并原地保持）。
2. 举手向裁判申请重启 / 维修。每轮最多一次，要裁判同意，最长 3 分钟，计入本轮时间。同意之前不碰任何东西。
3. 排除原因（常见的见第 6 节），例如重插相机线、`bash scripts/can_up.sh`。
4. 用剩下的时间和个数重新启动。`--targets` 里去掉已经放好的：

```bash
bash scripts/start.sh L1 --targets blue,green --no-wait \
    --set tasks.L1.time_limit_s=<剩余秒数> --set tasks.L1.required=<还没放好的个数>
```

5. 已经放进区域的物体不会再被抓（区域内部不参与识别，`perception.roi.exclude_zones`）。
6. 重启后再出故障就不要再修：停下，保留已经完成的有效任务。

注意：

- 停的时候夹爪里如果夹着物体：重启时程序先把夹爪再合拢 8 mm 检查（夹爪既没全开也没全合时），夹着东西就拒绝
  启动（exit code 2，`gripper is closed on something`），臂不动。把物体取出（或问裁判放回取物区）再启动。
- 重启时如果 TCP 低于搬运高度，程序先竖直抬到搬运高度，再去观察位（竖直抬起不可达时直接去观察位）。
- 按过 `e`（电子急停）以后，要把臂放回支架、断电重启，再 `bash scripts/can_up.sh`，很费时间。能用 `p` 就用 `p`。
- 程序从不自己重启，也不接着上次继续跑。

## 6. 出问题时怎么办

| 现象（屏幕上的字） | 先查 | 处理 |
|---|---|---|
| `can0 does not exist` | 适配器没插，或名字不同 | 第 2 步：插好后 `bash scripts/can_up.sh`；名字不同改 `robot.can_channel` |
| `can0 ... is DOWN`、bitrate 不是 1000000 | | `bash scripts/can_up.sh` |
| `BUS-OFF`、`ERROR-PASSIVE` | CAN 线、臂没上电 | 查线和电源，再 `bash scripts/can_up.sh` 重启链路 |
| `arm: cannot connect`、`no fresh joint feedback` | CAN、臂电源、别的程序占着臂 | 关掉官方 demo / agx_arm_ctrl；`bash scripts/can_up.sh` |
| `arm: not ready: ... TEACHING_MODE`，或工具说 drag-teach mode | 刚示教完；`check_setup --live` 打印固件版本和退出方式 | 先再按一次臂上的示教按钮；仍是 TEACHING_MODE 时：固件 S-V1.8-5 及以上，在 calib_verify / color_calib --observe 里输入 `c` 再输入 `CAN`（只使能，不动臂）；S-V1.8-5 以下，把臂拖回支架折叠到零位后输入 `x` 再输入 `EXIT`，或在支架上断电重启 |
| `exit_teach_mode refused: ...` | 臂没有折叠在零位（每个关节都要在 ±2.9° 以内） | 趁拖动模式还开着把臂拖回支架折叠好，松手再试；不行就在支架上断电重启 |
| `arm: not ready: ... EMERGENCY_STOP`、`the arm did not enable` | 急停按下过 | 松开急停；按过 `e` 的话把臂放回支架、断电重启 |
| run_task 刚启动就 `FAULT: ...`（相机），`camera: no frame within ...` | 驱动、话题名、ROS_DOMAIN_ID | `ros2 topic hz <话题>`；改 local.yaml 的 `camera.ros.*_topic`；诊断信息会写哪个话题没有消息 |
| 彩色和深度都有消息但 `never within sync slop` | 两路时间戳差多少：看诊断里的 `header stamps differ by X s` | X 小于 1 s：`--set camera.ros.sync_slop_s=0.1` 试，有效再写进 local.yaml。诊断说 different clocks（X 大于 1 s）：两路用了不同的时钟，加大 slop 没用；用 `ros2 param list \| grep -i time` 找驱动的时间源参数（time_domain / use_hardware_time 一类）改成同一个，改不了就设 `camera.ros.sync_mode: receipt` |
| CameraInfo 报 `unsupported distortion model`，或一直 `no valid CameraInfo`、每帧都丢 | 驱动发的畸变模型或系数不被支持 | 应急：`camera.ros.ignore_distortion: true`（按无畸变处理），或用 `camera.ros.intrinsics_override` 直接写内参。标成 plumb_bob 的 8 个系数已经自动按 rational 处理 |
| 深度没对齐：掩码整体偏离物体，或 `depth ... does not match color` | 驱动没开对齐 | 驱动加 `depth_registration:=true`；做不到时 `camera.ros.depth_registered: false`，并配 `depth_info_topic` 和 `depth_to_color`（4x4 T_color_depth） |
| `table: NOT FOUND`、`low_coverage` | 取物区太乱、外参错、深度无效 | 清空取物区再看；查外参；`perception.table.expected_z` 要等于实际桌面高度 |
| 外参方向错：位置差几十厘米、物体在桌面下、`pick polygon is behind the camera`、`projects outside the image` | 矩阵方向、法兰 / TCP、单位、子坐标系 | 第 4 步的 4 个问题；换写法 B；腕部相机核对 `parent_frame`（tcp 要带 `tcp_offset`）和 `child_frame`；然后第 8 步；还不行第 8b 步 |
| 外参加载失败：`needs "tcp_offset ..."`、`child_frame '...' is not a camera optical frame`、`rpy [...]: ... look like degrees` | 外参文件缺信息或单位不对 | 第 4 步：`parent_frame: tcp` 时补 `tcp_offset`（标定时驱动的值）；camera_link 一类的子坐标系补 `T_link_optical`；度写成 `rpy_deg` |
| 腕部相机（eye_in_hand）自检 WARN `... (eye_in_hand: checked at the observe pose)` | 臂不在观察位时腕部相机看不到取物区，正常 | 不用处理：run_task 移到观察位后会再查一次；看不到取物区就停在观察位，报 `pick area not visible from the observe pose`（exit code 3），查观察位和外参 |
| `table z differs from the taught table (perception.table.expected_z) by N mm` | 外参 z 方向有偏差，或 expected_z 不对 | 第 8 步：量 h，修正外参。安全检查和抓取高度用两者中较高的桌面 |
| 每个物体都偏同一个方向几毫米到 2 cm | 外参平移误差 | `calib_verify --apply`（允许的话） |
| `not reachable`，日志里 `blacklist ... unreachable` | 区域或观察位太远 / 太高 | 区域放在半径 0.40 m 以内；eye_in_hand 观察位放低；取物多边形不要包含臂够不到的地方 |
| `grasp_miss`（闭合后夹爪宽度接近 0） | 位置偏、抓得太浅 | 看 obs_*.jpg 和第 8 步的偏差；高度不对查 `robot.tcp_offset`；`grasp.max_grasp_depth` |
| 日志里 `grasp infeasible` | 物体比 `max_width - 5 mm` 宽 | 100 mm 夹爪时 `max_width: 0.100`；否则这个物体不抓 |
| `dropped`、`dropped_in_transit` | 夹持力小、抓得浅、速度快 | `robot.gripper.force` 加到 2–3 N；`grasp.grasp_depth_ratio` 调大；降速 |
| 两个挨着的方块认成一个，或一个被切成两半 | `perception.l1_block_size` 不对 | 量方块边长写进 local.yaml；实在不行 `perception.segmentation.merged_blocks: off` |
| 分类错 | L1 灯光；L2 样本少 | L1 第 9 步；L2 第 10 步加样本，或用 `onnx+knn`（docs/yolo.md）。分数低于 `perception.classifier.min_score` 的标成 unknown，不会被抓 |
| 时间不够，stop reason `timeout` | 速度、重试次数 | 提速；`runner.max_attempts_per_object: 2`。剩余时间少于 `runner.min_time_for_pick_s`（12 s）时不再开始新的抓取 |
| stop reason `timeout`，`detail: observation failures: ...` | 相机或识别一直失败（程序一直重试到时间用完） | 看 detail 里的原因（no frame、stale frame、perception error ……），按上面相机那几行查 |
| `gripper is closed on something`（exit code 2） | 夹爪里还夹着物体（重启时） | 第 5.3 节：取出物体再启动 |
| 抬起、放下或退回时手腕（joint6）突然转一大圈 | 直线运动跨过 roll ±180° | local.yaml 写 `robot.motion.linear_moves: false`（这几步改用 P2P 运动），再空跑确认 |
| `REFUSED: the self check failed` | 上面的 `[FAIL]` 行 | `check_setup --task <任务> --live` 会给每个 FAIL 写修复办法 |
| `REFUSED: --speed 50 is above robot.speed_percent 30` | 速度保护 | 加 `--allow-faster`，或改 local.yaml |
| `REFUSED: target 'yellow' is not a L1 label` | 拼写，或 labels 没配 | 改 `--targets` 或 tasks.yaml |
| 中途故障：stop reason `fault`，exit code 3 | 表下面的 `detail:` 行；summary.json 的 `fault_detail` | 第 5.3 节。程序不会自己重启 |
| 程序退出后终端不回显、按键不出字 | 终端还在单键模式 | 输入 `stty sane` 回车 |
