# 配置说明

所有参数都在 YAML 里。`config/default.yaml` 有全部默认值和英文注释；现场只写 `config/site/*.yaml`，不改
default.yaml。单位：长度 m，角度 rad；键名以 `_deg` 结尾的是度，以 `_s` 结尾的是秒。相对路径相对于包根目录
（`ws/src/cube_task`，环境变量 `CUBE_TASK_ROOT` 可改）。

## 1. 配置怎么合并

后面的覆盖前面的。字典逐层合并；列表和数值整个替换。

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | `config/default.yaml` | 默认值 |
| 2 | `config/site/tasks.yaml` | 手写：标签、类别到区域 |
| 3 | `config/site/poses.yaml` | `teach_poses` 写：观察位、区域、取物多边形 |
| 4 | `config/site/colors.yaml` | `color_calib` 写：HSV 区间 |
| 5 | `config/site/local.yaml` | 手写：其他现场值（速度、TCP、夹爪、相机话题） |
| 6 | `--config FILE`（可多次） | 临时加一个文件 |
| 7 | `--set key=value`（可多次） | 临时改一个键，值按 YAML 解析，例如 `--set robot.speed_percent=20` |

- 2–5 的文件名和顺序由 default.yaml 的 `site_overlays` 决定，不存在的文件跳过。local.yaml 最后合并，所以它里面
  的值会盖掉示教结果；不要在 local.yaml 里写 `zones`，除非就是要覆盖示教的区域。
- `--mode sim` 不读 config/site（避免把真机示教的区域带进仿真），而是合并场景生成的配置；加 `--site` 才读。
- `--mode replay` 和真机一样读 config/site。
- 外参文件不参与合并，由 `camera.extrinsics_file` 指向。
- 怎么确认最终生效的值：run_task 摘要第一行 `config:` 列出所有来源；每轮日志目录里的 `config.yaml` 是合并后的
  完整配置。

## 2. 现场文件和写它们的工具

| 文件 | 谁写 | 内容 |
|---|---|---|
| `config/site/tasks.yaml` | 手写（从 `config/examples/tasks.example.yaml` 复制） | `tasks.<任务>.labels`、`class_to_zone`、`order`、`classifier` |
| `config/site/poses.yaml` | `teach_poses`（工具用不了时照 `config/examples/poses.example.yaml` 手写） | `robot.poses.observe_joints`、`home_joints`、`zones.*`、`perception.roi.pick_polygon`、`perception.table.expected_z` |
| `config/site/colors.yaml` | `color_calib` | `perception.classifier.color.classes` |
| `config/site/local.yaml` | 手写（从 `config/examples/local.example.yaml` 复制） | 速度、TCP、夹爪、CAN 口、相机安装和话题、方块边长 |
| `config/site/extrinsics.yaml` | 官方文件复制；或 `calib_points`、`calib_verify --apply` | 相机外参（第 4 节） |
| `models/knn_model.npz` | `teach_classes` | KNN 样本和特征；旁边的 `knn_model_report.json` 是统计 |
| `models/detector.onnx`、`detector_labels.txt` | `tools/yolo/train_yolo.py` | YOLO 检测器（docs/yolo.md） |

- 工具写文件前把旧文件复制成 `<名字>.bak_<YYYYmmdd_HHMMSS>.<后缀>`，再原子地写新文件，并打印写了哪些键。
  `.bak_` 文件不会被合并；要回退就把它改回原名。
- 工具在 `--mode sim` 下写到 `~/vision_runs/sim_site/`，不会碰 config/site；`--site-dir DIR` 可以指定别的目录。
  要让别的工具用这些文件：`--config ~/vision_runs/sim_site/poses.yaml`（工具写完会打印这条提示）。
- config/site 的文件可以提交到 git；`*.onnx` 被 .gitignore 忽略，要另外备份。

## 3. 各配置项

只列现场可能要动的项。“现场”一栏：**必填** = 每个现场都要核对；**按需** = 出了对应问题再改。

### 3.1 robot（机械臂）

| 键 | 含义 | 默认 | 现场 |
|---|---|---|---|
| `robot.backend` | `pyagxarm` 真机 / `sim` | pyagxarm | 不改（sim、replay 模式自动设） |
| `robot.model` | `piper` / `piper_h` / `piper_l` / `piper_x` | piper | 官方臂型号不同时 |
| `robot.firmware` | pyAgxArm 固件选项 `default` / `v183` / `v188` / `v189` | default | 连接日志提示不匹配时 |
| `robot.can_channel` | CAN 口名 | can0 | 适配器名不同时 |
| `robot.speed_percent` | 默认速度，1–100 的整数 | 30 | 整轮通过后提速 |
| `robot.tcp_offset` | TCP（闭合时指尖中心）在法兰坐标系里的位姿 `[x y z roll pitch yaw]`，m / rad | `[0, 0, 0.1425, 0, 0, 0]` | **必填**：量法兰端面到指尖中心；z 必须在 0.05–0.25 之间 |
| `robot.gripper.max_width` | 夹爪最大开口，m | 0.100（100 mm 夹爪） | 现场全开夹爪核对读数 |
| `robot.gripper.force` | 夹持力，N（0–3） | 1.5 | 物体掉落时加大 |
| `robot.gripper.open_margin` | 下降前张开到“物体宽度 + 这个值”，m | 0.020 | 张开时碰到旁边的物体就减小 |
| `robot.gripper.close_width` | 抓取时的命令宽度，m | 0.0 | 很少 |
| `robot.gripper.empty_width` | 闭合后测得宽度小于它 = 没抓到（`grasp_miss`），m | 0.004 | 抓很薄的物体时减小 |
| `robot.gripper.settle_s` / `timeout_s` | 夹爪命令后等待 / 超时，s | 0.6 / 3.0 | 很少 |
| `robot.motion.pos_tol` / `rot_tol_deg` | “到位”的位置 / 姿态容差 | 0.006 m / 4° | 很少 |
| `robot.motion.require_motion_status` | 到位还要求控制器报 motion_status 0 | true | 固件从不报 0（每个动作都超时）时改 false |
| `robot.motion.feedback_max_age_s` | 反馈比这个旧就算通信故障，s | 0.5 | 很少 |
| `robot.motion.linear_moves` | 抬起、放下、退回和恢复动作走直线（move_l）；false = 这几步改用 P2P（move_p） | true | 现场看到这几步手腕突然转一大圈（roll 跨过 ±180°）时改 false |
| `robot.workspace.x` / `y` / `z` / `r_min` / `r_max` | TCP 允许的范围（基座坐标系），m | 见 default.yaml | 场地限制更严时缩小 |
| `robot.workspace.max_tilt_from_down_deg` | 工具最多偏离竖直向下多少度 | 30 | 很少 |
| `robot.poses.observe_joints` | 观察位的 6 个关节角，rad | null | `teach_poses` 的 `o` 写 |
| `robot.poses.home_joints` | 零位姿态（仿真臂的初始关节角），rad | 全 0 | `teach_poses` 的 `h` 写，可选 |
| `robot.poses.observe_tcp` | 没示教观察位时的备用观察位 `[x y z 闭合角]` | `[0.20, 0, 0.15, 1.5708]` | 示教后不用；真机自检对它报 WARN，应该用 teach_poses 示教 observe_joints |

### 3.2 camera（相机）

| 键 | 含义 | 默认 | 现场 |
|---|---|---|---|
| `camera.backend` | `ros` 真机 / `file` 回放 / `sim` | ros | 不改（各模式自动设） |

| `camera.frames_to_average` | 每次观察取几帧，逐像素取深度中值 | 3 | 深度噪声大时加到 5 |
| `camera.settle_s` | 臂停下后等多久再取图，s | 0.4 | 腕部相机图像有拖影时加大 |
| `camera.frame_timeout_s` / `max_frame_age_s` | 等一帧的超时 / 帧最大年龄，s | 2.0 / 1.0 | 很少 |
| `camera.ros.color_topic` | 彩色图话题 | /camera/color/image_raw | **必填**（按实际话题） |
| `camera.ros.depth_topic` | 深度图话题 | /camera/depth/image_raw | **必填** |
| `camera.ros.info_topic` | 彩色图的 CameraInfo | /camera/color/camera_info | **必填** |
| `camera.ros.depth_registered` | 深度已经对齐到彩色 | true | 驱动不能对齐时改 false |
| `camera.ros.depth_info_topic` / `depth_to_color` | 软件对齐用：深度的 CameraInfo、4x4 T_color_depth | /camera/depth/camera_info / null | 只在 depth_registered 为 false 时用 |
| `camera.ros.depth_scale` | 16 位深度的单位换算到 m（32 位浮点深度已经是 m） | 0.001 | 深度单位不是 mm 时 |

| `camera.ros.intrinsics_override` | 直接给彩色图内参 `{fx, fy, cx, cy, width, height, dist}`，不再需要 CameraInfo | null | 现场应急：驱动不发或发错 CameraInfo 时 |
| `camera.ros.qos_reliable` | false = 传感器 QoS（best effort） | false | 很少 |
| `camera.ros.start_timeout_s` | 启动时等第一对图像，s | 5.0 | 很少 |
| `camera.ros.yuv422_order` | `uyvy` / `yuyv`，给标错 yuv422 编码的驱动 | uyvy | 彩色图颜色错乱时 |
| `camera.file.dir` / `loop` / `repeat` | 回放目录、循环、每帧重复次数 | | `--replay-dir` 自动设 |

| 键 | 含义 | 默认 | 现场 |
|---|---|---|---|
| `perception.l1_block_size` | L1 方块边长，m。用来切开挨在一起的同色方块 | 0.05（官方 50 mm ± 2 mm） | 一般不改 |

| `perception.segmentation.max_height` | 物体最高，m | 0.25 | 很少 |

| `perception.segmentation.color_split` | 一个实例里有两种方块颜色时按颜色切开 | true | 很少 |
| `perception.segmentation.max_occlusion_ratio` | 轮廓被更近的物体挡住超过这个比例就不抓 | 0.2 | 很少 |
| `perception.classifier.backend` | 任务没写 `classifier` 时用的分类器 | color | 不改，用 `tasks.<任务>.classifier` |
| `perception.classifier.min_score` | 分数低于它标成 unknown（不会被抓） | 0.55 | 误分类多时加大 |
| `perception.classifier.color.classes` | 每种颜色的 HSV 区间（OpenCV：H 0–180，S、V 0–255），多段取并集 | 6 种颜色 | `color_calib` 写 |
| `perception.classifier.color.min_fraction` | 实例像素里落在获胜颜色区间的最低比例 | 0.35 | 很少 |
| `perception.classifier.knn.model_file` / `k` / `max_distance` | KNN 模型、近邻数、最大距离（标准化后的 RMS 距离，更远 = unknown）；每个特征的标准差有下限（颜色直方图 0.05、尺寸 3 mm 等），训练里没出现过的颜色占一点（例如 2 %）不会让物体变成 unknown；旧模型文件照常加载 | models/knn_model.npz / 3 / 3.0 | `teach_classes` 写模型 |
| `perception.classifier.onnx.*` | YOLO 检测器 | | 见 docs/yolo.md |
| `perception.tracking.match_dist_m` | 两次观察里中心距离小于它算同一个物体；也是失败物体的黑名单半径，m | 0.03 | 很少 |
| `perception.debug_image` | 生成叠加图（日志里的 obs_*.jpg） | true | 不改 |

### 3.5 zones（放置区域）

`teach_poses` 的 `z` 写，也可以手写（放在 poses.yaml）：

```yaml
zones:
  zone_red:
    center: [0.21, 0.29, 0.0]     # 区域底面中心 [x, y, 底面 z]，基座坐标系，m
    size: [0.10, 0.10]            # 沿区域自身 x、y 的边长，m
    yaw: 0.0                      # 区域 x 轴相对基座 x 轴的角度，rad
    wall_height: 0.0              # 平垫子 0；容器写壁高，m
  fruit_bin:
    center: [0.19, 0.315, 0.0]
    size: [0.14, 0.14]
    wall_height: 0.05
    release_height: 0.03          # 可选：只对这个区域覆盖 place.release_height
```

区域名随便取，但必须和 `tasks.<任务>.class_to_zone` 里的名字一致。自检会检查区域中心、角点和放置位姿是否在
工作空间内，以及放置位姿是否可达。

### 3.6 tasks（任务）

| 键 | 含义 | 默认 |
|---|---|---|
| `tasks.<T>.time_limit_s` | 本轮限时，s | L1 180，L2 300 |
| `tasks.<T>.required` | 本轮要放好的个数 | L1 3，L2 6 |
| `tasks.<T>.classifier` | `color` / `knn` / `onnx` / `onnx+knn` | L1 color，L2 knn |
| `tasks.<T>.labels` | 本轮的类别名 | L1 [red, green, yellow]，L2 空 |
| `tasks.<T>.class_to_zone` | 类别 -> 区域名。不在这里的类别永远不抓 | 空 |
| `tasks.<T>.order` | 固定的抓取顺序（标签列表），`--targets` 会覆盖它 | 空 |

`--targets` 的个数少于 `required` 时，要同时 `--set tasks.<T>.required=<个数>`，否则放完会报 INCOMPLETE。

### 3.7 runner（一轮的流程）

| 键 | 含义 | 默认 | 现场 |
|---|---|---|---|
| `runner.selection` | 先抓哪个：`nearest` 离基座最近 / `score` 分类分数最高 / `isolated` 周围空间最大 | nearest | 物体挤在一起时试 isolated |
| `runner.max_attempts_per_object` | 一个物体最多试几次，之后放弃它 | 3 | 时间紧时改 2 |
| `runner.max_failures_per_label` | 一个标签失败这么多次后，只要还有别的目标可抓就先抓别的；null = 2 × max_attempts_per_object | null | 很少 |
| `runner.max_empty_observations` | 连续几次成功的观察都没有可抓目标就结束（`no_targets`）。相机 / 识别失败不算：一直重试到时间用完（连续 5 次失败后每 2 s 试一次），这样结束时 detail 写 `observation failures: ...` | 4 | 很少 |
| `runner.min_time_for_pick_s` | 剩余时间少于它时不再开始新的抓取（`timeout`），s | 12.0 | 按实测单次抓放时间调 |
| `runner.observe_retry_s` | 没有目标或观察失败后等多久再观察，s（连续 5 次失败后至少 2 s） | 0.5 | 很少 |
| `runner.start_on_enter` | 到观察位后等回车再开始计时；`--no-wait` 设为 false | true | 比赛规则决定 |
| `runner.return_home_at_end` | 正常结束后去哪：home 原点（`robot.poses.home_joints`，低位先竖直抬起）、observe 观察位、false 不动 | home | 很少 |
| `runner.rescan_radius_m` | 放置后只重拍刚抓走的物体这个范围内还有物体的视角，m；-1 = 每次都重拍；0 = 不重拍，直接抓下一个（现场 local.yaml） | 0.12 | 物体容易被碰动时调大 |
| `runner.partial_length_ratio` | 长条类别看到的长度不到 nominal_footprint 的这个比例时算只拍到一部分，不从这个视角抓 | 0.6 | 很少 |
| `runner.dry_run_hover` | 空跑时停在抓取 / 放置位姿上方多高，m | 0.05 | 很少 |

## 4. 外参文件格式

### 4.1 坐标系约定

- 基座坐标系 `base`：PiPER 基座，z 向上，x 向前（臂伸出去的方向），y 向左。
- `flange`：link6 法兰，就是 SDK `get_flange_pose()` 报告的位姿。
- `tcp = flange @ pose6_to_T(robot.tcp_offset)`，闭合时的指尖中心。
- 相机坐标系：**彩色**图像的光学坐标系，x 向右、y 向下、z 朝前。内参也是彩色图像的。
- 外参矩阵 `T_<父>_camera` 把相机坐标系里的点变到父坐标系：`p_父 = T @ p_相机`。
  - 只有腕端相机（eye_in_hand）：父 = `flange`（T_flange_camera）。固定相机的标定（父 = `base`、
    T_base_camera、`mount: eye_to_hand`）会被拒绝。文件里写 `tcp`（T_tcp_camera）时必须带 `tcp_offset`（标定时
    驱动的 TCP 偏移，m / rad），加载时换算成 T_flange_camera，所以 `robot.tcp_offset` 不影响相机位姿。程序在每次
    取图时用当时的法兰位姿算 `T_base_camera = T_base_flange @ T_flange_camera`，所以取图时臂必须是静止的。
- 外参的子坐标系 `child_frame` 必须以 `_optical_frame` 结尾（不区分大小写）。给的是 camera_link 这类 ROS 机体
  坐标系（REP-103：x 前、y 左、z 上）时，加 `T_link_optical`（4x4，或 translation + quaternion，来自
  `ros2 run tf2_ros tf2_echo camera_link camera_color_optical_frame`），加载时算 T_父_optical = T_父_link @
  T_link_optical；两者都没有时拒绝加载。
- 欧拉角 `[roll, pitch, yaw]`：R = Rz(yaw) · Ry(pitch) · Rx(roll)，和 PiPER SDK 的 pose6 一样。

### 4.2 能读的写法

`core/extrinsics.py` 的 `load_extrinsics()` 按扩展名（.yaml / .yml / .json / .npy）或内容判断格式：

| 写法 | 键 | 说明 |
|---|---|---|
| 我们的格式（工具写出的） | `mount`、`parent_frame`、`child_frame`、`matrix`、`translation`、`quaternion`、`source`、`rms`、`stamp` | 路径是 .json 时写 JSON（说明在 `_comment` 里），其他扩展名写带注释头的 YAML（头里有可读的 t（mm）和 rpy（度））；不能写 .npy |
| 4x4 矩阵 | `matrix` 或 `T` | 父坐标系看 `parent_frame`，没写时是 flange |
| 带名字的矩阵 | `T_flange_camera` / `T_tcp_camera` | 键名决定父坐标系（`T_base_camera` 拒绝） |
| 反方向的矩阵 | `T_camera_flange` / `T_camera_tcp` | 加载时自动求逆 |
| 平移 + 旋转 | `translation` + `quaternion`（x, y, z, w）或 `rotation`（3x3）或 `rpy`（弧度）或 `rpy_deg`（度） | 向量可以写成列表或 `{x: , y: , z: }`；`rpy` 里绝对值大于 2π 的角拒绝（多半是度，改用 `rpy_deg`） |
| xyz + 欧拉角 | `xyz` + `rpy` / `rpy_deg` | 同上 |
| handeye_calibration_ros 的 JSON | `position` + `orientation`（x, y, z, w） | 没写 parent_frame 时按 flange 处理并警告；写 `parent_frame: tcp` 时要加 `tcp_offset` |
| 裸矩阵 | 4x4（或 16 个数）的列表、纯文本矩阵、.npy 数组 | 按 T_flange_camera 读 |

加载时的检查（不通过就报错，自检 FAIL，run_task 拒绝启动）：

- mount 只能是 eye_in_hand；文件或 `camera.mount` 写 eye_to_hand、或父坐标系是 base，都拒绝加载。
- 平移长度 ≥ 3 m 直接拒绝（多半是毫米写成了米）。
- 旋转必须是正交矩阵（误差 1e-3 以内，小误差会自动正交化并打印一条日志）。
- 同一个文件里同时有几种写法（例如 matrix 和 translation + quaternion）时，它们必须一致（1e-4 m、1e-3 rad），
  否则报 `disagree`。手改了其中一种，就把另外几种删掉。
- `parent_frame: tcp`（或 `T_tcp_camera` / `T_camera_tcp`）没有 `tcp_offset` 时拒绝；`child_frame` 不是光学坐标系
  又没有 `T_link_optical` 时拒绝（见 4.1）。
- 扩展名是 .json 但内容不是 JSON 时，按 YAML 读并打印警告（旧版工具写坏的 .json 外参仍能读）。

例子见 docs/现场流程.md 第 4 步（写法 A–D）。腕部相机的例子（仿真里的腕部相机：法兰 -x 方向 7 cm、法兰面前方
3 cm，光轴和工具 z 平行）：

```yaml
mount: eye_in_hand
parent_frame: flange
translation: [-0.07, 0.0, 0.03]
quaternion: [0.0, 0.0, -0.7071, 0.7071]
```

检查一个外参文件能不能读、读出来是什么（不动臂）：

```bash
python3 -c "from cube_task.core.extrinsics import load_extrinsics as L; \
print(L('config/site/extrinsics.yaml').describe())"
```

输出例如 `eye_in_hand T_flange_camera: t = [-70.0, 0.0, 30.0] mm, rpy = [0.00, -0.00, -90.00] deg, ...`。

## 5. 常用的临时改法

| 目的 | 参数 |
|---|---|
| 这一轮降速 | `--speed 20` |
| 这一轮提速（高于 robot.speed_percent） | `--speed 50 --allow-faster` |
| 只放 1 个就结束 | `--set tasks.L1.required=1` |
| 重启后按剩余时间 | `--set tasks.L1.time_limit_s=95` |
| 试一个外参文件 | `--set camera.extrinsics_file=/path/ext.yaml` |
| 试一个 KNN 模型 | `--set perception.classifier.knn.model_file=/path/knn.npz` |
| 换分类器 | `--set tasks.L2.classifier=onnx+knn` |
| 不等回车直接开始 | `--no-wait`（run_task） |
| 把日志放到别处 | `--log-dir /tmp/runs` |
| 合并一个额外的文件 | `--config my.yaml` |

`--set` 的值按 YAML 解析：`--set a.b=null`、`--set a.b='[0.1, 0.2]'`、`--set a.b=true` 都可以。
